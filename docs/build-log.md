# 제작 기록

그록이 커밋만 봐도 무슨 문제가 있었고 어떻게 막았는지 알 수 있게 남긴다. 코드 설명은 README에 있다.

## 2026-10-29 — 주소 입력과 기능 초안

문제: 저장소가 비어 있었다. 폴더 이름 `QATool`에 대문자가 있어 Next 생성기가 프로젝트를 거부했다.
해결: 패키지 이름을 `preflight-qa`로 두고, 만든 파일을 이 저장소 루트로 옮겼다.

문제: Next 16 기본 템플릿은 페이지 캐시를 켠다. 검사 결과는 방금 저장한 파일이라 캐시하면 이전 결과가 보일 수 있다.
해결: 캐시를 끄고, 첫 화면과 결과 화면은 요청마다 파일을 읽는다.

문제: Playwright를 Next 번들에 넣으면 페이지를 여는 브라우저가 실행되지 않는다.
해결: `next.config.ts`의 `serverExternalPackages`에 `playwright`를 넣었다.

문제: 아무 주소나 받으면 이 컴퓨터 안의 페이지나 비밀번호가 섞인 주소까지 열게 된다.
해결: http/https 공개 주소만 받는다. localhost, 사설 IP, 비밀번호가 들어 있는 주소는 거절한다. 같은 사이트는 `www`와 맨 도메인만 따라가고 서브도메인은 가지 않는다. 최대 15페이지. 로그인, 결제, 폼 제출은 하지 않는다.

문제: 이 컴퓨터에 모델 API 키가 없다. 기능 초안은 모델이 만든다.
해결: 키가 없어도 페이지 수집과 화면 캡처는 저장한다. 기능 목록만 비우고, 화면에 `.env.local`의 `LLM_API_KEY`를 넣으라고 보여 준다. 주소와 모델 이름은 `LLM_BASE_URL`, `LLM_MODEL`로 바꾼다. 기본값은 xAI 호환 주소와 `grok-4`다.

문제: 결과 화면의 캡처가 가장 큰 그림인데 늦게 읽힌다는 경고가 떴다.
해결: 그 그림에 `loading="eager"`를 넣었다. 다시 열었을 때 경고는 나오지 않았다.

문제: 폼 칸에 type이 없으면 태그 이름 `input`으로 저장됐다.
해결: type이 없는 입력 칸은 `text`로 적는다.

확인:

- `https://example.com`을 화면에 넣고 제출했다. 약 4초 뒤 결과 화면이 열렸고, 제목 Example Domain, 상태 200, 화면 캡처가 보였다. 기능 초안은 키가 없어 비었다. 이 페이지는 h1 같은 제목 태그를 쓰지 않아 제목 목록은 비었다.
- `https://httpbin.org/html`에서는 제목 `Herman Melville - Moby-Dick`을 읽었다.
- `https://httpbin.org/forms/post`에서는 고객 이름, 전화, 이메일, 크기, 토핑, 배달 시간, 요청 사항과 Submit order 버튼을 읽었다. 폼은 제출하지 않았다.
- `localhost`와 `192.168.0.5`는 결과 없이 거절 문장만 나왔다.

아직 없는 것: 기능 목록 수정, 테스트 케이스, 자동 실행, `/report/[id]`.
